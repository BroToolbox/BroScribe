# Brand files

BroScribe's artwork, from the BroScribe design system (built on the Bros
brand kit). Edit only `src/`; everything else here is generated.

- `src/mascot-*.svg`, `src/tile-hero.svg`: the kit's mascot and app-icon
  tile, with the shared ids made unique (`shell-fill`, `visor-fill`, so
  resvg fills the shell and visor) and the ear-cup waveform on both cups.
- `src/tile-glyph.svg`: the app-icon tile for 16–24 pixels, where the face
  no longer reads: the waveform in the ear cups' violet (brand guide: the
  glyph below 32 px, the face from 32 up).
- `src/waveform.svg`, `src/status-*.svg`, `src/visor-smile.svg`: single-ink
  glyphs the app paints in the text colour (`svg()` uses them as masks).
- `src/menubar-*.svg`: the status item's glyphs (idle, recording, paused),
  black on transparent; every system's status icon comes from them.

Regenerate after changing a source, then commit the results:

    cargo run -p broscribe-app --example render_brand

It writes, from the same sources, each system's own format:

| Output | What |
| --- | --- |
| `*.svg` | each source as plain paths (the mascot's `Bro_` set in the bundled Inter, so no installed font is needed) |
| `AppIcon.iconset/` | macOS app icon, on Apple's 824/1024 icon grid |
| `menubar/` | macOS status item: template images, 24×18 points at 1x and 2x |
| `windows/BroScribe.ico`, `windows/BroScribe.res` | Windows app icon, as an icon file and as the compiled resource the `broscribe-app` and `broscribed` build scripts link (icon group 1) |
| `windows/tray-<state>-<light\|dark>.ico` | Windows notification area, 16–48 px, dark ink for a light taskbar and light ink for a dark one |
| `linux/broscribe-<state>-symbolic.svg` | Linux status item: symbolic icons (filled shapes in `currentColor`) that GTK and KDE panels paint in their own text colour |
| `linux/tray-<state>-<size>.png` | Linux status item pixmaps for hosts that cannot load the symbolic name (22, 32, 44, 64 px): light ink in a dark ring |
| `linux/window-icon.png` | the X11 window icon, 128 px |

App icons use the waveform tile below 32 pixels and the hero tile from 32
up. The square status icons centre each state's drawing at one scale for
all three states; the macOS menu-bar images share a 24×18-point canvas across
all three states (with `menubar-idle.svg` centred and recording/paused
leaving room for the dot or bars), so neighbouring icons never shift.

## Theme colours

`../themes/broscribe.json` and `../../src/ui/palette_gen.rs` are generated by
`docs/redesign/tools/palette.py --theme-json` from the design system's
`docs/redesign/proto/ds/color.css`; edit the CSS or the script, never the
outputs, and run it again (`--check-generated` and `scripts/tests/test_palette.py`
fail while they disagree). The JSON holds gpui-component's keys in four
variants (light, dark and their Increase Contrast versions); the Rust table
holds the roles gpui-component has no key for, read through `ui::brand`.

`ui::brand`'s tests port `palette.py`'s checks over all four variants: body
text 7:1, secondary text and state words 4.5:1, marks, edges and the focus
ring 3:1, labels on every solid fill 4.5:1 at rest, under the pointer and
pressed, and the danger, warning and success colours at least 20 apart (15
under Increase Contrast) under protanopia, deuteranopia and tritanopia, with
their soft fills at least 5 apart. `ui::theme`'s tests refuse unknown keys and
check the same pairs through the theme keys the components read.
